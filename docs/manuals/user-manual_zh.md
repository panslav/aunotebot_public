# 用户指南

## 版本 0.37.0.0

记录中检测到日期或时间时会显示日历导出按钮，“更多”菜单中始终可用。按钮显示费用 0.10 积分。点击后直接发送 .ics 活动文件及备用 Google 日历链接，无需机器人内的中间预览。用日历打开文件并确认导入；Telegram 或操作系统可能会要求选择应用。无法保证在 iOS、Android 或电脑上自动打开默认日历。

只有日期时创建全天活动；只有时间时使用已保存时区的今天，即使该时间已过。日期和时间都有时使用指定时刻。默认时长为 60 分钟。标题以笔记或任务图标开头并使用记录标题；描述包含返回机器人中记录的链接，不包含私密正文。日期缺失、无效或有歧义时，“更多”会要求输入一个开始日期和/或时间；返回可取消，附件和转发会创建新草稿。

每位用户对同一活动仅首次成功获取时付费。再次获取免费，机器人重启后也一样；发送失败会退还积分。更改标题、日期或时间会生成新活动。机器人无法确认是否已保存至日历。重复导入可能生成重复活动；记录后续修改不会同步。关闭记录显示的附件时，文件会从聊天中移除。不需要连接日历账户，也不使用付费 AI 解析。

朗读会保留作者和来源链接，包括笔记与任务互相转换之后。Tambur.pub 等没有协议前缀的链接会通过 HTTPS 打开，不再显示为原始 Markdown。

生成语音的实际时长会被测量并保留，重新打开条目时仍会显示。同一文本使用相同声音和模型重复朗读时，会复用已保存的文件，不再产生新的 AI 生成费用或重复附件。修改朗读文本后会创建新版本。来源不明的旧音频文件不会被自动删除。

## 版本 0.36.0.1

附件和转发消息会创建新草稿，不会被当作提醒日期，即使晚间摘要仍在等待回复。提醒建议不会开启日期输入；如需手动输入日期，请明确打开“提醒”。

新建和重新打开的草稿始终显示“AI 笔记”和“AI 任务”操作，包括纯文本草稿。点击 AI 操作时仍会检查权限和余额，普通保存操作仍然可用。

当提及的人触发分享或分配建议时，“返回”只关闭该建议，保留之前的界面、页码和附件。“返回条目”仍是单独的操作。

## 版本 0.36.0.0

每日奖励在第一次符合条件的操作时发放，而不是午夜。新建条目或评论（包括任务完成评论）必须超过 100 个可见字符；向他人分享或分配条目不受长度限制。同一本地日期不会重复发放，也不会重算历史余额。新手奖励和单独的分享奖励保留原规则。

搜索按相关性显示所有匹配条目，并使用标准分页。从条目返回时会恢复原查询和页码，不会再次收取 AI 搜索摘要费用。

AAC 音频在本地无重新编码封装为 M4A 后再转写，原始附件不变。只有 Markdown 文档附件、没有正文的草稿会显示清晰的说明和文档数量。

待处理草稿的按钮会保留在主卡片上，直到点击；打开其他草稿或导航不会移除它们。保存、关闭或删除条目时会移除机器人显示的附件副本，包括正在发送的文件；原始传入消息会保留。

网站来源不会重复，正文中的普通链接会保留。每个转发片段按“作者：消息”显示；仅在 Telegram 提供原消息链接时添加作者链接。私密或隐藏转发可能没有该链接。编号段落中的多个链接会保留。不会批量重写旧草稿。

## 版本 0.35.0.9

设置提醒后返回单一任务页面，不再重复显示任务列表。关闭条目会移除聊天中显示的附件；再次打开同一条目时，会复用已显示的文件。

搜索结果中的 ID 可打开对应条目，每行使用该条目标题中的图标。

合并的转发消息保留每个片段的发送者。AI 会综合条目正文、OCR 和支持的附件内容（包括视觉信息），生成一份统一摘要，并保留段落和列表的换行。

设备上的文件下载由 Telegram 控制；下载期间预览可能仍然模糊。不支持或过大的文件无法完整分析。

本指南说明如何在 Telegram 中使用 AUNotebot。

维护说明（v0.25 音频限制澄清）：本机器人对通过 Telegram 上传的音频执行 Telegram Bot API 下载限制。

## 2. 语言
1. 首次 `/start` 时，机器人会尝试根据 Telegram 语言环境检测你的语言。
2. 默认回退语言是英语。
3. 如需手动更改语言：
   - 打开 `更多 -> 设置 -> 语言`
   - 按以下顺序选择一种语言：`English`、`Español`、`Français`、`Português`、`Русский`、`Українська`、`简体中文`、`العربية`
4. 选择后，所有核心 UI 标签和按钮都会翻译为所选语言。

## 2a. AI 积分与 Telegram Stars
1. AI 驱动的操作会使用你的积分余额。
2. 默认计费模型：
   - `1 积分 = 1 Telegram Star`
   - 首次使用机器人时一次性赠送 `10 免费积分`
   - 每个活跃的本地日期最多赠送 `0.50 免费积分`：首次创建超过 100 个可见字符的条目或评论，或成功向其他用户分享或分配条目时发放。不活跃的日期、浏览、编辑和接收副本均不获得此奖励。
   - 创建笔记/任务不再自动奖励积分
   - 文本转语音：`1.5 积分 / 分钟`
   - 音频解析：`0.25 积分 / 分钟`
   - 将已附加到保存项目的音频/视频转为文字：`1 积分 / 分钟`
   - 图片 OCR：`0.1 积分` / 张
   - 文本/链接分析：`0.05 积分` / 次
3. 对于已保存媒体的 `🤖 用 AI 分析`，机器人会读取 Telegram 附件中保存的时长，并按秒以 `1 积分 / 分钟` 比例计费。
   - 示例：`125 秒` 的费用是 `2.09 积分`。
   - 费用向上取整到最接近的 `0.01 积分`。
   - 如果旧的已保存附件没有时长，机器人会按 `60 秒` 处理。
   - 如果余额不足，转写不会开始，现有笔记/任务不会改变。
4. 打开 `更多 -> 积分` 可以：
   - 查看当前余额
   - 查看最近 5 条积分操作
   - 打开完整积分历史
   - 查看当前 AI 价格
   - 使用 Telegram Stars 充值
5. 你可以在 `更多 -> 设置 -> 联系人 -> 分享我的电话` 中分享自己的电话号码。
6. `更多 -> 设置` 还包含一个危险区选项，可删除你的 AUNotebot 账户数据。
7. 删除全部数据会永久移除机器人拥有的笔记、任务、草稿、提醒、联系人、设置、积分历史和关联账户记录。
8. 在机器人内购买积分时，Telegram Stars 充值直接以 `XTR` 计价。
9. 如果余额不足：
   - 该次 AI 功能会被阻止
   - 机器人会显示通知
   - 非 AI 功能仍可继续使用
10. 常见付费 AI 操作包括：
   - 摘要和标签
   - Recall/Find 答案生成
   - 翻译
   - 自由格式提醒、时区和 digest 时间解析
   - 转写和文本转语音

1. 向机器人发送普通文本。
2. 机器人会显示草稿预览。
3. 点击 `📝 保存为笔记`。
4. 笔记列表会打开。

## 4. 创建任务
方式 A：
1. 发送文本。
2. 在草稿预览中点击 `🟧 保存为任务`。
3. 任务列表会打开。

方式 B：
1. 打开任意笔记。
2. 点击 `⬛ 转为任务`。

## 5. 转发消息
1. 将一条或多条消息转发给机器人。
2. 机器人会把时间相近的转发消息合并为一个草稿。
   - 默认合并时间是 `30` 秒。
   - 你可以在 `更多 -> 设置 -> 多条消息合并时间` 中修改。
3. 如果你在转发后立即添加普通文本，机器人会将其追加为：
   - `💬 转发时附带评论：`
   - `<你的文本>`
   并放在来源/页脚行之前。
4. 在笔记/任务视图中，公开 Telegram 用户来源会显示为可点击的 `@handle`，而不是原始 `https://t.me/...` URL；最终 `通过 Telenota 保存 (...)` 页脚之前会保留且仅保留一行空行，并且当 Telegram 仍然提供原始消息时，该页脚还会包含一个可点击的 `您的消息` 链接，指回创建该条目的那条机器人消息。
5. 如果转发消息包含一个或多个网页链接，机器人会先使用每个页面可用的预览元数据；如果没有这些元数据，则尝试从页面元数据中安全地提取确定性的标题（`og:title`、`twitter:title` 或 HTML `<title>`）。
   - Google Maps 的重定向链接在目标页面暴露标题时，可以解析为最终页面标题。
   - 如果无法提取安全标题，机器人会保留现有的“保存来源链接”fallback，而不会显示伪造来源或原始错误。
   - 在合并转发中，后台链接摘要更新只会替换待处理的链接块，并保留其他转发消息。
6. 当 Telegram 向机器人提供转发文本格式时，保存后的笔记/任务会保留这些格式：
   - 粗体、Markdown 风格斜体、链接和引用块会在最终项目视图中渲染。
   - 链接会保留完整目标 URL，包括 `?g_st=...` 或 `&foo=...` 等查询参数。
7. 如果转发后没有添加单独评论，机器人会保存明确标记 `转发时没有评论`；如果转发后立即发送了评论，则评论块中只保存该评论。
8. 转发消息附带的 Telegram 媒体会随草稿保存，并与保存后的笔记/任务一起显示。如果多个附件保存了来源链接，项目视图会按媒体类型分组，以逗号分隔的紧凑来源链接显示：
   - 当 Telegram 将照片/图片作为机器人可下载媒体提供时，这些图片会保留为附件。
   - 仅由 Telegram 客户端生成的链接预览图片可能无法通过 Bot API 下载；如果需要保证图片保留，请发送/转发实际照片。
   - 如果 Telegram 同时暴露了转发的视频或动画以及客户端预览图，机器人会保留真实的视频或动画，并抑制重复的预览图片。
   - 如果 Telegram 在 AI 保存期间只报告转发媒体文件过大，机器人会保存原始草稿，不进行 AI 媒体分析，而不是显示通用错误。
9. 可选：保存前发送只包含 hashtag 的文本（例如 `#work #idea`）以添加标签。
10. 打开草稿并使用：
   - 第 1 行：`📝 保存为笔记`、`🟧 保存为任务`
   - 可选附加行：当草稿文本包含可识别日期/时间时，会显示 `⏰ 保存为提醒`
   - 最后的操作：`✏️ 编辑`、`❌ 取消`
   - 草稿始终显示 AI 保存操作，包括纯文本草稿；对于图片，条目先保留原始内容，再显示 AI 摘要和 OCR 文本，并尽量保留可识别的编号列表和项目符号列表
   - AI 摘要会整理为三个简短部分：引言、主体和结论
   - `编辑` 只显示可手动复制的纯净正文；来源、条目类型本地化标签和机器人页脚仍由模板生成

新草稿会以所选界面语言获得简洁的 AI 生成标题。视频 AI 分析会先描述画面，包括可读日期，再在可用时添加音频转写。
11. 点击保存后，机器人会立即显示保存状态，然后显示成功消息，并提供四个内联快捷按钮：第一行是打开已创建项目和对应列表，第二行是开始和草稿。
12. 如果所有草稿都已处理/保存，打开 `草稿` 会返回主页选择器。

## 6. 语音和视频
1. 发送语音消息、音频文件（包括 Telegram 以音频或音频文档发送的 `.m4a`）、视频或视频笔记。
2. 当开始解析音频/视频时，机器人会立即显示处理状态消息。
3. 机器人会转写并准备草稿。若可用，音频/视频转写会在每个转写段落末尾包含时间戳。
   - 如果转写失败，机器人会显示 `重试`；点击它即可使用同一个 Telegram 文件重试，无需重新上传。
4. 点击 `📝 保存为笔记` 或 `🟧 保存为任务`。
   - 保存后，机器人会显示成功消息，并提供四个内联快捷按钮：第一行是打开已创建项目和对应列表，第二行是开始和草稿。
5. 如果草稿包含可识别日期/时间，你可以点击 `⏰ 保存为提醒`。
   - 这会将草稿保存为任务，并立即安排提醒。
6. 如果草稿合并了多条转发/带说明消息或 AI 媒体分析，保存后的笔记/任务会用可见水平分隔线分隔各部分。Telegram 向机器人提供格式时，原始文本和生成内容的格式会被保留。
7. 大于 `20 MB` 的 Telegram 语音、音频和视频文件会在处理前被拒绝，因为在当前机器人运行方式下 Telegram Bot API 不允许本机器人下载更大的上传文件。
8. 如果你的录音或视频大于 `20 MB`，请手动拆分或压缩后逐个发送较小部分。
9. 临时错误消息会在你发送下一条消息、点击下一个机器人按钮或 30 秒后自动移除。
10. 可恢复的 Telegram、AI 或超时故障会显示稳定代码，例如 `E-TIMEOUT-001`。请求帮助时请将该消息转发给 `@telenota_chat`；该代码不会泄露你的内容。

## 7. 图片和截图
1. 发送或转发图片/截图。
2. 机器人会运行 OCR，并总结可见的重要文字/内容。
3. 系统会创建草稿；之后你可以保存为笔记或任务。
4. 如果你发送的是可提取文本的 PDF 文档，并选择 AI 保存操作，机器人会保留草稿原始内容，追加提取出的 PDF 文本，然后再追加不超过 `300` 个词的 AI 摘要，语言为你选择的界面语言。
5. 提取文本会保留清晰的段落结构，AI 摘要会渲染为三个简短部分：引言、主体和结论。
6. 扫描版 PDF 或仅由图片组成的 PDF 目前可能无法完成 AI 分析，直到后续加入 PDF OCR 支持。
7. 如果你在不使用 AI 的情况下保存 PDF，草稿/条目会保留一行简单的 `PDF <文件名>`。之后如果你打开已保存条目并点击 `AI 分析`，也会复用同一个 PDF 摘要流程。
8. Telegram Bot API 不会向机器人提供转发故事的媒体文件。机器人会保存故事引用，并要求你在下一条消息发送截图、照片或下载的视频；该文件会附加到同一草稿。
9. 对图片进行 AI 分析时，保存的条目会先显示 AI 摘要，再显示识别出的 OCR 文本。图片中的编号列表和项目符号列表会保留其格式。

  - `📚 更多`
- 如果启用了底部菜单（`更多 -> 设置 -> 显示底部菜单`）：
  - 第 1 行：`📝 笔记` + 换行 + `(N)`，`⏰ 提醒` + 换行 + `(N)`，`🟧 任务` + 换行 + `(N)`
  - 第 2 行：`🗂️ 草稿` + 换行 + `(N)`，`🔎 查找`，`📚 更多`
- 列表标题（如 `📝 笔记` 和 `🗂️ 草稿`）会显示为一条可见单行，不再带有隐藏的占位空白。
- 当你从第 2 页或更后页面打开任务，然后将其标记为完成、删除、转换或设置提醒时，机器人再次显示任务列表时会返回同一页。
  - 启用后，底部菜单会保持可见，直到用户在设置中将其关闭
  - 这些按钮打开的屏幕与汉堡菜单操作相同。
- 也可以使用开始屏幕上的 inline 计数器：
  - 第 1 行：`📝 笔记 (N)`、`🟧 任务 (N)`
  - 第 2 行：`🗂️ 草稿 (N)`、`⏰ 提醒 (N)`
  - 第 3 行：`🔎 查找`、`📚 更多`

## 9. 查找（合并搜索 + Recall）
1. 点击 `🔎 查找`（开始屏幕或汉堡菜单），或使用 `/find`。
2. 机器人会进入交互式查找模式并显示：
   - `🔎 你可以问我任何问题！我的 AI 会为你查找并总结信息。`
3. 发送任意自由格式查询/问题。
4. 机器人会同时执行：
   - 对笔记和任务（包括已归档项目）进行确定性排序
   - 对查询词变体进行词形感知匹配（例如名词词尾变化）
   - 对相关结果进行 AI 摘要
5. 找到项目时，机器人回复格式为：
   - 摘要文本
   - `以下是与你的请求最相关的项目：`
   - 相关项目按钮（最相关的在前）
   - `⬅️ 返回`
6. 如果你的 Find 查询是精确项目 ID（例如 `219` 或 `#219`），并且该项目存在，它会固定为结果第 1 条。
7. 点击 `⬅️ 返回` 可退出查找模式。
8. `⬅️ 返回` 会回到进入查找模式之前所在的屏幕。
9. 如果可选的 AI 摘要不可用，本地匹配和结果按钮仍会显示，并提供中性的备用摘要。

## 9a. 提醒建议
1. 如果新创建的笔记或任务包含可能的日期/时间短语，机器人会自动建议提醒。
2. 如果只识别到日期，机器人会提供 `早上`、`中午`、`晚上`，以及 `设置提醒` 和 `跳过`。
3. 当这个提示仍然打开时，你可以直接输入自定义日期/时间；不再需要单独的“手动设置”按钮。
4. 如果只识别到时间，机器人默认使用当天日期，除非你自己输入其他日期。
5. 如果项目仍是普通笔记，而你选择 `设置提醒`，机器人会先将其转换为任务，然后安排提醒。
6. 创建提醒后，机器人会用你的语言确认提醒时间。
7. 如果你从媒体回调中打开提醒设置，机器人会使用安全的编辑回退并且仍然显示提醒提示。

  - 第 1 行：`🤖 用 AI 分析`、`🔊 生成语音`

### 通过联系人分配任务
1. 打开一个任务。
2. 点击 `👥 分配`（或 `👥 重新分配`）。
3. 机器人会显示：
   - 你已保存的联系人按钮
   - 手动输入选项（`@handle` 或手机号）
4. 如果你输入新的有效 `@handle`/手机号，它会自动保存到你的联系人中。
5. 如果接收人已经启动过机器人，任务分配会发送并与该用户关联。
6. 如果接收人还没有启动机器人，并且你选择了 `@handle`，机器人会生成可复制的邀请码链接。把它发送给接收人：当对方用该链接启动机器人时，如果 Telegram handle 匹配，任务会自动送达。如果另一个账号打开链接，机器人会让你批准或拒绝访问。
7. 你可以在分配选择器中使用 `↩️ 取消分配` 来移除当前分配。

### 通过联系人分享笔记
1. 打开普通笔记。
2. 点击 `📤 分享`。
3. 机器人会显示：
   - 你已保存的联系人按钮
   - 手动输入选项（`@handle` 或手机号）
4. 如果你输入新的有效 `@handle`/手机号，它会自动保存到你的联系人中。
5. 如果接收人已经启动过机器人，笔记会被分享并发送到对方聊天中（包括附件）。
6. 如果接收人还没有启动机器人，并且你选择了 `@handle`，机器人会生成可复制的邀请码链接。把它发送给接收人：当对方用该链接启动机器人时，如果 Telegram handle 匹配，笔记会自动送达。如果另一个账号打开链接，机器人会让你批准或拒绝访问。

### 生成语音（文本转语音）
1. 打开任意笔记或任务。
2. 点击 `🔊 生成语音`。
3. 机器人会立即显示系统通知，说明文本转语音生成已开始。
4. 机器人使用 OpenAI（`onyx` 声音）生成语音消息，发送到聊天中，并将其附加到该项目。

### 媒体转文字
1. 打开任意笔记或任务。
2. 打开 `📚 更多`。
3. 点击 `🤖 用 AI 分析`。
4. 这个按钮现在也适用于普通文本条目和图片附件，而不只是音频/视频/PDF。
5. 机器人会按实际分析路径计算费用：
   - 文本/链接类 AI 丰富化使用文本分析费率
   - 已保存图片使用图片分析费率
   - 已保存音频/视频按 Telegram 已存时长以 `1 积分 / 分钟` 计费，并向上取整到最接近的 `0.01 积分`
6. 如果余额足够，机器人会预留所需积分，执行 AI 分析，更新条目，并且只在处理成功后最终扣费。
   - 若可用，追加的音频/视频转写会在每个转写段落末尾包含时间戳。
7. 如果 AI 分析失败，预留积分会释放，条目保持不变。

## 17. 设置
打开 `⚙️ 设置` 可以配置：
- `🌐 语言`（第一项）
  - English / Español / Français / Português / Русский / Українська / 简体中文 / العربية
- `🕒 时区`

  - 删除 / 归档 / 保留

  - 复制笔记文本 / 不执行任何操作
- `🗓️ 每日任务摘要`
  - `设置时间`（自由格式文本，例如 `每天早上 8 点`、`21:30`、`明天 7 点`）
  - 保存时间也会自动启用每日摘要
  - `启用` / `禁用`
  - 在设置中，状态仅以绿色/红色圆点显示
  - 设置摘要显示本地时间，不附加时区后缀
  - 摘要每天按用户配置的本地时间发送一次
  - 摘要包括以下部分：
    - `提醒`（或 `下次摘要前没有提醒`）
    - `任务`
    - `上次摘要后新增的笔记`
  - 所有部分中的项目都是链接；点击会在机器人中打开相关笔记/任务
  - 摘要消息包含快捷按钮：`⏰ 提醒`、`🟧 任务`
  - 设置摘要与摘要详情屏幕之间的状态保持同步
- `🌙 晚间总结`
  - `设置时间`（与早间摘要相同的自由格式时间解析器）
  - 保存时间也会自动启用晚间总结
  - `启用` / `禁用`
  - 在设置中，状态仅以绿色/红色圆点显示
  - 设置摘要显示本地时间，不附加时区后缀
  - 晚间摘要包括：
    - `任务 -> 我今天完成的任务`
    - `任务 -> 我今天创建的任务`
    - `我今天添加的笔记`
  - 摘要之后，机器人会询问：
    - `你自己感觉今天过得怎么样？`
    - 请针对这个具体提示回复文字/语音/视频
    - 机器人会把你的回复保存为带 `daily` 标签的笔记
- `⏱️ 多条消息合并时间`
  - 点击按钮
  - 发送秒数，例如 `30`、`45`、`120`
  - 在该时间间隔内发送的消息会合并为一个草稿
  - 如果间隔为 `30` 秒或更长（默认设置），则会创建新草稿
- `📱 显示底部菜单`
  - 状态仅以绿色/红色圆点显示
  - 默认：启用
  - 启用时，会为该用户显示持久底部键盘
  - 禁用时，会为该用户隐藏持久底部键盘
  - 更改此设置是静默的，不会发送额外可见性系统消息
- `📚 显示条目数`
  - 控制列表屏幕中每页显示多少项目

联系人管理位于 `更多 -> 设置 -> 联系人`：
- 查看所有已保存的分配联系人
- `➕ 添加联系人`（输入 `@handle` 或手机号）
- `📱 分享我的电话`（将你自己的 Telegram 联系方式分享给机器人）
- 打开联系人 -> `编辑` / `删除`
- 编辑会更新分配建议中使用的联系人值

- `合并` 建议现在会优先显示标签相近的条目，且不使用 AI；语义 AI 排序默认不启用，因为它会增加额外费用和延迟。

## 最新更新 (0.36.2.phase4-5)
- 草稿预览在保存前可显示红/绿翻译开关。红色保留原文；绿色会在普通保存笔记或任务时翻译为你的界面语言。
- AI 生成的笔记/任务摘要现在使用你选择的界面语言，即使原文是其他语言。
- 快速连续转发的消息会按到达顺序合并。
- 从媒体消息打开的合并界面现在会安全回退，不再显示 Telegram 编辑错误。
- 转发相册现在按顺序保存，以保留每张图片、视频和说明文字的原始顺序。转发投票会保存选项和可用结果的文本快照；没有结果时，会添加提示，要求在原始投票中投票。
- 对明确写出的地址行，机器人可以提供精确的 OpenStreetMap 匹配。只有在确认并保存笔记或任务后，地点才会作为独立的位置评论添加。

## 最新更新（0.36.4）
- 评论会保留 Telegram 格式，并使用“保存”、“❌ 删除”和“返回”按钮；返回或删除时也会清除旧的评论页面。
- 只有 Telegram 提供数据时，投票快照才显示各选项票数和总票数。否则，Telenota 会明确标记结果未知，绝不会虚构零票。
- 机器人可在直接发送和转发的消息中识别明确地址，包括多语言街道缩写。只会将提取出的候选地址发送给 OpenStreetMap，且不会添加含糊的匹配结果。

## 版本 0.35.0.4
- AI 标题会使用可用文本、链接摘要及受支持附件的分析结果。仅含附件的草稿在分析前会保留清晰的媒体类型标题。
- 已保存项目的 AI 分析会先合并项目文本与所有受支持附件提取出的文本，再追加分析结果。
- 在合并转发中，每个消息片段都会先显示作者，再显示片段文本。提醒建议在任一操作后消失；“跳过”只跳过提醒。

## Release 0.35.0.5
- 合并的转发内容会在每段文字前显示对应作者。
- AI 摘要显示在 OCR 或附件提取文本之前。
- 设置页面使用简短的本地化标题；按钮文字的对齐方式由 Telegram 客户端控制。
- 只有明确回复晚间反思提示的内容才会保存为反思。摘要后单独发送的文字、链接或文件会创建普通草稿，不会被过期的输入模式拦截。
